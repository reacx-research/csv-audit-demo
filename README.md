# CSV audit and cleanup

An original, local CSV audit/cleanup CLI for Python **3.9+**, using only the standard library. It delivers a cleaned CSV, a machine-readable audit, an explicit rejected-record file and a cell-level change log. The bundled example is entirely synthetic; it is a portfolio demonstration, not a customer engagement.

## Run

From this directory, run a default audit into a fresh output directory:

```bash
python3 csv_audit.py fixtures/messy.csv /tmp/csv-demo-default
```

Or explicitly approve trimming, blank-row rejection and normalized deduplication:

```bash
python3 csv_audit.py fixtures/messy.csv /tmp/csv-demo-cleanup \
  --whitespace trim --blank-rows reject --dedupe normalized
```

These particular examples return **exit code 1** because they deliver exclusions requiring review. Output files still exist. Choose a fresh directory for each run: existing artifacts are never overwritten.

## Exactly what the rules mean

| Option | Default | Effect when enabled |
|---|---|---|
| `--whitespace preserve / trim / collapse` | `preserve` | `trim` removes Unicode whitespace at cell edges. `collapse` also replaces internal whitespace runs, including newlines/tabs, with one space. |
| `--blank-rows keep / reject` | `keep` | `reject` sends empty physical records and rows consisting entirely of whitespace/empty fields to the rejected-record audit. |
| `--dedupe none / exact / normalized` | `none` | Keeps the first matching record. `exact` compares the resulting cell strings. `normalized` additionally trims cell edges and uses Unicode NFC for comparison. Comparison is case-sensitive; the retained row's spelling is preserved. |
| `--max-rows N` | `10000` | Limit counts data records, excluding the header. A quoted multiline cell is one record. Exceeding the limit stops delivery. |

Headers retain their names and original column order. Missing cells are never invented. Numbers, IDs, dates and empty values remain text. Default processing retains duplicate records, whitespace and blank records; it makes zero intentional cell-value edits.

A nonblank record with too few or too many columns is excluded from the cleaned CSV **and fully preserved in the rejected audit**, including its parsed values, physical line range and raw record text. No padding or truncation occurs. This is an auditable partition of the source, not silent deletion.

UTF-8 and UTF-8 with BOM are supported. A source BOM is retained in the cleaned output. Output record separators are LF and CSV quoting is regenerated by Python's CSV writer; the cleaned file is not promised to be byte-identical to the source. The original file itself remains byte-identical, with its SHA-256 checked before processing and again through delivery.

Malformed headers, invalid UTF-8 or CSV parser errors such as an unterminated quoted record are fatal. No new output files are published in these cases. The program does not guess where a broken quoted record ends. Header names must be nonblank and exactly unique.

## Deliverables

- `cleaned.csv`: retained records, with only approved cell edits.
- `audit.json`: rules, input/output hashes, measured counts, source name, original-file integrity result and full excluded-record details.
- `rejected.csv`: record number, physical line bounds, reason, explanation, raw record and parsed values as JSON.
- `changes.csv`: exact old/new values and column positions for changed cells in retained records. Excluded rows appear in the rejected audit instead.

Rows are numbered starting at **1 for the first data record**, independently of the physical line number. Multiline quoted records explain why these numbers can differ.

Exit codes: **0** = delivered without excluded records; **1** = delivered with excluded records to review; **2** = fatal input/destination error. In-place output, symlinks/hardlinks pointing to the source, and existing output artifacts are refused. On a write failure, only files created by that invocation are removed.

## Test and verify

```bash
python3 -m unittest discover -s tests -v
python3 check.py
```

Tests cover quoted commas/quotes, multiline text, Unicode/BOM, malformed headers/quoting, row-width auditing, no-loss defaults, all 18 cleanup-policy combinations, normalized deduplication, the 10,000-record boundary, source hashes, linked-file overwrite refusal and CLI exit codes. `check.py` independently regenerates both example deliveries in temporary directories, compares every published artifact byte for byte and checks the report's measured counts and original fixture hash.

The checked-in `fixtures/default/` and `fixtures/cleanup/` outputs came from the commands above. `fixtures/malformed-quoting.csv` and `fixtures/malformed-header.csv` are deliberately invalid test examples. All input rows and names are fictional.

The CLI has no network access, dependencies to install, account integrations or data enrichment. A client must approve the rules before a paid cleanup. See `REPORTportfolio.md` for the reproducible portfolio case and `SERVICE-OFFER.md` for the proposed fixed-scope service.
